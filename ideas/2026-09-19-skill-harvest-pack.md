## Concept

Sell a **same-week agent skill harvest pack** when a solopreneur, freelancer, or 1-5 person shop has a messy week of real jobs and a folder of other people's skills that do not match how they actually work.

The customer uploads or exports:

- 3-10 finished jobs from the last 7 days (threads, tickets, proposals, research dumps, GTM sequences, WhatsApp/Telegram traces)
- the tools the agent or human actually used
- optional: one 10-minute voice note on "what I always correct after the agent drafts"
- optional: any skill files they already tried and abandoned

Agents plus one human operator return within 48 hours:

1. A job-to-skill map: which finished jobs are one skill, which are two, which are not reusable.
2. Three paste-ready skills in a boring, loadable format (name, when-to-use, inputs, tools, steps, never-do, one eval case each).
3. A cited harvest ledger: every step in a skill points at a source job id or is marked `invented-and-cut`.
4. A "do not install" list of trendy public skills that fight this shop's actual week.
5. One human-role note: what the operator still owns after the three skills load (the Asefi inversion, one page).
6. A source appendix. No theater methodology. No untitled mega-skill.

This is **not** a skill registry, **not** a video studio, and **not** an enterprise GTM operating system. It is a productized desk that turns last week into three skills the shop will actually run next week.

## Target user

- Primary buyer: EU/UK/US indie hackers, freelancers, and tiny GTM / agency / local shops already running coding agents or WhatsApp/Telegram "AI employees," drowning in public skill catalogs.
- Urgent pain: they bookmark OpenAI / Superpowers / Montage skills and still re-explain the same job every Monday.
- Existing workaround: paste a system prompt and hope, or hire someone to "set up agents" who leaves a folder of unused markdown.

## Why this works

- Market signal: skills registries and AI-native GTM launched in the same week. The missing object is *this shop's* skills, cited from work they already did.
- Agent advantage: cluster jobs, extract repeated steps, refuse steps that never appeared in the traces, write eval cases from real outputs.
- Solo-operator advantage: one person who has corrected the same draft ten times can name the never-do line a registry author will not.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept zip/PDF/PNG/JSON/chat export/voice. Detect job boundaries. Refuse to merge two businesses.

**Agent 2 — Cluster.** Group jobs by repeated verb and tool set. Flag one-off heroics as `not-a-skill`.

**Agent 3 — Skill writer.** Draft three skills with inputs, tools, steps, never-do, and one eval case each. Every step needs a source id.

**Agent 4 — Conflict check.** Compare harvest against any public skills the buyer already installed. List collisions.

**Human operator.** Cut invented ceremony, strip secrets, export Markdown + PDF. The model does not publish skills to a public registry and does not connect to the buyer's production agent.

Stack to start: coding agents, one transcriber, one LLM, Stripe Payment Link, a mailbox. Exports only in week one.

## Risks and mitigations

- Fake skills: if a step is not in the traces, do not keep it. Mark `invented-and-cut`.
- Client secrets in skills: redaction pass, delete raw traces after 30 days unless they opt into the retainer.
- Overlap with judgment-rule harvest (2026-09-16): that pack extracts *exceptions the human still decides*. This pack extracts *repeatable jobs the agent may run*. Sell both; do not merge files.
- Overlap with golden-set eval (2026-09-18): that pack scores an existing agent. This pack writes the skill the eval should score. Route "my agent is already live and lying" buyers to 2026-09-18.
- Overlap with approval-lane (2026-09-19): that pack writes execute rights. This pack writes how to do the job once rights exist. Keep the files separate.
- Scope creep into building their whole GTM OS: three skills, one format conversion as an add-on. Stop.
