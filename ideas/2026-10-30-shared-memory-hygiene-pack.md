**Date:** October 30, 2026

- Adjacent: freelancers being told to sell knowledge not tasks, and ongoing notes that shared context files rot without deliberate hygiene.

The catalog already has skill-safety & context-floor packs (progressive disclosure, stale-context cutoffs, third-party skill risks), handoff contracts, maintainability floors, and teammate rosters. It does not have a productized pack that turns the actual shared markdown/session files a solo is already using into an inspectable hygiene ledger of ownership, receipts, and update rules so the cleanup stops being manual and continuous.

## Concept

Sell a **same-week shared memory hygiene pack** when a solopreneur, indie hacker, or freelance operator is already running more than one agent (or one agent across many sessions) and the shared context is a pile of markdown files, session notes, and traces that keep going stale or conflicting.

The customer uploads (or pastes):

- the current shared context files (markdown, notes, prompts that reference other files)
- recent agent traces or session logs that show context loss or cleanup work
- a short description of the agents and what they are supposed to share
- optional: notes on what has already gone wrong (conflicting facts, missing receipts, manual cleanup time)

Agents plus one human operator return within 48–72 hours:

1. Ownership and freshness ledger: which file or section owns which fact, with stale-cutoff rules and last-known-good markers.
2. Required receipt fields: the exact citations, timestamps, or source pointers every agent must attach when it writes or updates shared memory.
3. Conflict and escalation rules: what to do when two agents write different values for the same fact, or when a file is older than the cutoff.
4. Paste-ready update templates and prompt/wrapper language that force the hygiene rules on the next run.
5. Source ledger: every rule cites the provided files/traces or is marked “operator assumption.”

This is **not** a full memory system, **not** a vector store or external database, **not** live enforcement, and **not** a rewrite of the agents. It is a productized desk that turns “I keep cleaning the markdown so the agents stop contradicting each other” into inspectable ownership and receipt rules the solo can paste the same week.

## Target user

- Primary buyer: solopreneurs, indie hackers, and freelance operators (EU/UK/US) already running multi-agent or multi-session workflows that share context via files.
- Urgent pain: agents drop context, write conflicting facts, or force the human to manually clean markdown before every new run; no shared definition of who owns what or what receipt must travel with an update.
- Existing workaround: giant shared prompts, manual copy-paste cleanup, or keeping agents isolated so they never share memory.

## Why this works

- Market signal: today’s posts treat file-based cross-agent memory and scattered company knowledge as active friction after basic reliability and skill safety. The missing artifact is a cited hygiene pack for the files the buyer already has, not another general memory architecture tip.
- Agent advantage: parse scattered markdown and traces, surface ownership gaps and conflicts, draft concrete receipt and cutoff rules, and produce ready-to-paste templates overnight.
- Solo-operator advantage: one person who has watched agents fight over or ignore shared files can kill vague “keep the context clean” language, tighten the rules to real blast radius, and deliver a pack the buyer can implement in under 45 minutes of review.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept shared files, traces, and job description. Normalize, assign ids, flag missing ownership or receipt patterns.

**Agent 2 — Gap mapper.** Extract current sharing patterns, surface conflicts and stale sections, flag missing receipts. Mark unknowns.

**Agent 3 — Floor drafter.** Write the ownership/freshness ledger, receipt fields, and conflict rules. Cite sources.

**Agent 4 — Implementation writer.** Produce the starter update templates and prompt/wrapper language that force the hygiene rules.

**Human operator.** Remove vague rules, tighten cutoffs so they match real cost of conflict, confirm receipt fields are actually checkable, and export Markdown + PDF. Do not rewrite live agents or add external stores.

Stack to start: existing coding/browser agents, one LLM, plain Markdown, Stripe Payment Link, mailbox. No product UI until the fifth paid job.

## Risks and mitigations

- Invented rules: every field cites provided files/traces or is marked “not specified — operator assumption.” Operator rejects drafts that invent tool behaviors.
- Confidential files and traces: isolated processing, no training on client materials, delete after 30 days unless they opt in.
- Overlap with skill-safety/context-floor, handoff, or maintainability packs: this pack is specifically the hygiene of the shared markdown/session files the buyer is already using for multi-agent memory, not progressive disclosure of skills, a handoff contract between agents, or one-sentence ownership notes on finished artifacts. Implementation stays with the buyer.
- Buyer expects a live memory system or automatic cleanup: deliver the pack for the materials provided and stop. Runtime stores or enforcement are a separate engagement.
- Thin materials: if the customer has only a vague description and no actual shared files or traces, return a short gap list and partial refund rather than invent a hygiene floor.
