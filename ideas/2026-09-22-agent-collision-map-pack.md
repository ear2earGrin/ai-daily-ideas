## Concept

Sell a **same-week agent collision map pack** when a solopreneur, freelancer, or 1-5 person shop is running three or more agents (email, support, social, coding, booking, research) against the same tools and cannot say which agent is allowed to send, edit, or delete.

The customer uploads or exports:

- a roster: agent names, tools they touch, what they are "supposed" to do (even a 6-minute voice note is enough)
- 7–14 days of traces: sent-mail folders, CMS revision history, calendar change log, Notion/Linear activity, n8n/Make run history, coding-agent session titles
- optional: one screenshot of the last "why did this send twice" incident

Agents plus one human operator return within 48 hours:

1. A roster card per agent: purpose, read surfaces, write surfaces, `not-in-record`.
2. A surface ownership matrix: Gmail / calendar / CMS / repo / ads / Stripe / Notion tagged `single-writer` / `shared-read` / `collision` / `unowned`.
3. A collision ledger: dated events where two agents (or an agent and the human) wrote the same object. Cite the log line or mark `guess-from-name`.
4. Three paste-ready decisions only: one surface that gets a single writer this week, one agent that is demoted to draft-only, one human review gate. Each with a 7-day test.
5. A one-page "do not touch" card the operator can paste into every agent system prompt.
6. A source appendix. No invented orchestration platform. No "just buy a multi-agent OS."

This is **not** a multi-agent runtime, **not** Akai for enterprises, and **not** live locking. It is a productized desk that makes last week's write conflicts inspectable.

## Target user

- Primary buyer: EU/UK/US solopreneurs, indie hackers, and freelance shops running 3–25 agents across email, content, code, and bookings.
- Urgent pain: two replies went to the same lead, the CMS draft was overwritten overnight, or the calendar double-booked after they "added a scheduling agent."
- Existing workaround: turn agents off, put everything through one ChatGPT tab, or pretend the coordination engine is a Notion page nobody updates.

## Why this works

- Market signal: today's X feed named 25-agent stacks, $100 installed assistants, agent-team programs, and "the coordination engine" as the hard part. Enterprise screen-to-workflow tools do not ship a file a solo can use on Thursday.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept zip/CSV/PDF/PNG/JSON/voice. Detect tools and date range. Refuse to merge two businesses in one pack.

**Agent 2 — Roster builder.** Normalize each named agent to purpose + surfaces. Flag unnamed automations as `unowned`.

**Agent 3 — Collision miner.** Join activity exports on object id / subject / URL / timestamp window. Tag `proven-collision` / `guess-from-name` / `clean`.

**Agent 4 — Pack writer.** Matrix, ledger, three decisions, do-not-touch card. Every cell has a source id or `not-in-record`.

**Human operator.** Kill fake orchestration advice, drop secrets, export PDF + Markdown. The model does not log into their Gmail and does not disable agents live.

Stack to start: coding agents, one transcriber, one LLM, Stripe Payment Link, a mailbox. Exports only in week one.

## Risks and mitigations

- Fake certainty: if the export has no actor column, do not invent which agent wrote. Circle `unowned` or `guess-from-name`.
- Credentials in traces: isolated processing, redaction pass, delete after 30 days unless they opt into the retainer.
- Overlap with approval-lane (2026-09-19): that pack designs who may *approve* a side effect. This pack maps who already *writes*. Sell both; do not merge the files.
- Overlap with session handoff (2026-09-17): that pack resumes one unfinished run. This pack maps many live agents against shared tools.
- Overlap with undo (2026-09-20): that pack rolls back a bad write. This pack tries to stop the next collision. Mention undo as an upsell after a proven overwrite.
- Scope creep into becoming their orchestration SaaS: three decisions and a prompt card. Stop.
