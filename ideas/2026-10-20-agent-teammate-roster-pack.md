**Date:** October 20, 2026

The catalog already has standardization, governance, spend, and access packs. It does not have a productized roster that splits agents by project, writes the SOPs they need, and isolates context so multi-business solos can actually delegate.

## Concept

Sell a **same-week agent teammate roster pack** when a solopreneur, indie hacker, or small-agency operator is juggling multiple projects or businesses and wants agents that behave like specialized teammates instead of a confused generalist.

The customer uploads (or pastes):

- a short list of active projects/businesses and what “done” looks like for each
- rough workflow notes, existing SOPs, or “how I do this today” bullets
- optional: current tools, agent platform, and pain points (context mix-ups, repeated corrections)

Agents plus one human operator return within 48–72 hours:

1. A roster table: one row per project with proposed agent role name, single job description, primary tools, and isolation boundary.
2. End-to-end SOP outlines for the 2–4 highest-leverage workflows (step-by-step, inputs/outputs, decision points).
3. Escalation and review rules: what the agent must flag, when to pause, and what the human still owns.
4. Starter prompts or skill stubs that embed the project context and SOP.
5. Source ledger: every role or step cites the customer’s notes or is marked “not specified — operator assumption.”

This is **not** a full agent implementation, **not** platform setup, and **not** ongoing management. It is a productized desk that turns messy multi-project reality into an inspectable team charter a solo can hand to agents the same week.

## Target user

- Primary buyer: solopreneurs, indie hackers, and freelance operators (EU/UK/US) running 2–8 projects or micro-businesses who already use Claude, Cursor, n8n, or similar and feel context switching or “easier to just do it.”
- Urgent pain: agents keep mixing business context, SOPs are in their head, and review time is exploding because the agents do not know the boundaries.
- Existing workaround: one giant chat, ad-hoc prompts, or manually rewriting instructions every time they switch projects.

## Why this works

- Market signal: today’s posts treat “agents as project teammates + better SOPs” as the practical way one person runs multiple businesses. The missing artifact is a cited roster that makes the split explicit.
- Agent advantage: extract workflows from notes, draft role charters and SOPs, enforce citation, and produce ready-to-paste prompts overnight.
- Solo-operator advantage: one person who has run multi-project setups can kill vague roles, tighten SOPs, and deliver a pack the buyer can implement in under 45 minutes of review.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept project list and notes. Normalize, assign project ids, flag missing “done” criteria.

**Agent 2 — Workflow mapper.** Extract repeated steps, decision points, and tools. Flag gaps as “not specified.”

**Agent 3 — Roster & SOP drafter.** Write project-scoped roles, isolation rules, SOP outlines, and escalation criteria. Cite sources.

**Agent 4 — Prompt stub writer.** Produce starter prompts or skill outlines that embed the charter.

**Human operator.** Remove vague or invented steps, tighten language, confirm isolation makes sense, and export Markdown + PDF. Do not implement or connect the agents.

Stack to start: existing coding/browser agents, one LLM, plain Markdown, Stripe Payment Link, mailbox. No product UI until the fifth paid job.

## Risks and mitigations

- Invented workflows: every step cites provided notes or is marked “not specified — operator assumption.” Operator rejects drafts that add unstated processes.
- Confidential project details: isolated processing, no training on client notes, delete after 30 days unless they opt in.
- Overlap with generic prompt services: the pack is specifically a project-scoped roster + SOPs from *their* materials, not generic agent advice. Implementation stays with the buyer.
- Buyer expects full setup: deliver the pack and stop. Connecting tools or running the agents is a separate engagement.
- Low-quality input: if notes are too thin, return a short gap list and partial refund rather than invent a team.
