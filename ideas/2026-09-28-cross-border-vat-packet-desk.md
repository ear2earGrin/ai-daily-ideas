## Concept

Sell a **same-week cross-border VAT packet** when an EU/UK-adjacent solo already has Stripe, PayPal, Etsy/Shopify, or a marketplace payout file — and no bookkeeper who lives in OSS/IOSS.

The customer uploads or points at:

- last 7–31 days of Stripe / PayPal / Lemon Squeezy / Paddle exports
- shipping or marketplace CSVs (destination country, incoterms if any)
- last OSS/IOSS or local VAT return they filed (PDF or spreadsheet)
- refund and chargeback rows for the same window
- optional: one fight ("the German buyer says VAT was wrong")

Agents plus one human operator return within 48 hours:

1. A country floor: destination, rate used in the file, rate that should apply, `match` / `mismatch` / `draft-unverified`.
2. A packet card per sales channel (max 4 in pack one): taxable base, VAT collected, refunds, marketplace-deemed-supplier vs own-store.
3. A last-window receipt: totals only from their files. No invented savings.
4. A 7-line filing card: what can be pasted into OSS this cycle, what is paused, what a human must confirm.
5. A first-week script: one export habit, one refund tagging rule, one "do not let an agent invent a rate."
6. A source appendix citing file names and row ranges.

This is **not** a full accounting firm, **not** tax advice, and **not** an auto-filer. It is a productized desk for *one seller, one window of exports*, so the next OSS paste is a file instead of a guess.

## Target user

- Primary buyer: EU indie sellers, digital product shops, and small makers (BG/RO/PL/ES/IT/DE/NL/FR) who sell across borders and file OSS themselves or with a cheap accountant who hates their CSVs.
- Urgent pain: Q4 volume + a refund or marketplace payout that does not match last quarter's rate table; the owner cannot explain a line without rebuilding a pivot.
- Existing workaround: Excel at midnight, ChatGPT on a CSV, or paying an accountant after the window closed.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept CSVs and last-return PDFs. Detect one seller. Refuse a 12-entity group in pack one.

**Agent 2 — Line joiner.** Map destination country, channel, taxable base, collected VAT, refunds. Tag marketplace-deemed vs own-store.

**Agent 3 — Rate checker.** Compare used rate vs the seller's last return and a pinned official rate table. Mark mismatches. Never invent a rate.

**Agent 4 — Pack writer.** Country floor, channel cards, receipt, filing card, first-week script. Every number cites a file or `draft-unverified`.

**Human operator.** Kill tax-advice language, drop VAT IDs from the public sample, export PDF + Markdown. The model does not file OSS and does not email the tax office.

Stack to start: coding + browser agents, one LLM, Stripe Payment Link, a mailbox. Exports only in week one.

## Risks and mitigations

- Acting as their tax advisor: never file, never sign, never tell them "you owe X." Show cited lines and mismatches.
- Overlap with quarterly tax folder (2026-09-14): that pack is a US-style estimated-tax folder. This pack is EU cross-border VAT lines.
- Overlap with late-invoice chase (2026-09-07): that pack collects unpaid invoices. This pack reconciles tax on money already moved.
- Overlap with agent spend attribution (2026-09-21): that pack attributes inference cost. This pack attributes destination VAT.
- Secret-stuffed exports: strip VAT IDs and buyer emails from working copies when not required. Halt if live bank tokens appear.
- Rate tables change: pin the table date on every pack. If the table is stale, mark `draft-unverified`.
