## Concept

Sell a **same-day ranking-signal posting card** to a solo builder who posts on X (or a similar public feed) and cannot tell whether yesterday's thread died because of the hook, the link, the reply habit, or because they never matched a signal the ranking code actually names.

The customer sends:

- a handle, or a paste of the last 14 original posts (replies optional).
- the signal source they want scored against. Default: the public X recommendation / ranking repo they name, plus the README sections they care about. If they do not name one, the operator uses the current public algorithm repo and quotes the file.
- optional: the one audience they are trying to reach (other agent builders, a local trade, a niche newsletter).
- optional: one post they believe should have traveled and did not.

Agents plus one human operator return within one business day:

1. A signal list pulled from the named public source, each line quoted with a file path. No signal that is not in that source.
2. A 14-post scorecard: which documented signals each post hit, which it missed, and `not-in-record` where the public code does not say what happened to that post.
3. Three drafts aimed at the audience they named, each tagged with the signal it is trying to hit. No promised impressions.
4. A do-not-do line: the one habit in the last 14 posts that the source does not reward (link-only posts, no reply, off-audience bait).
5. A source appendix. No claim that the card reverse-engineered a private ranking, saw their analytics, or guarantees reach.

This is **not** a growth agency, **not** a bot that posts for them, and **not** an impression forecast. It is a productized desk that makes a public signal list inspectable against a real feed.

## Why this works

- Market signal: the 7 Oct post is explicit that the ranking code is public and that brands will pay for a strategy built on it. The 6 Oct solo-builder post is the buyer: someone already shipping, looking for other builders, not for another agent framework.

- Solo-operator advantage: one person who posts can tell a draft that matches a documented signal from a draft that only sounds like the timeline. The model is the clerk. Judgment is which of the three drafts is allowed to go out.

## Execution plan (one person + agents)

**Agent 1 — Intake.** Accept a handle or a paste, plus the signal source URL. Refuse DMs, private analytics exports, and other people's unpublished drafts.

**Agent 2 — Signal clerk.** Read only the named public repo. Quote each ranking signal with path and line. If the file does not name a signal, do not invent one.

**Agent 3 — Score clerk.** Score the 14 posts against that list. Mark misses and `not-in-record`. Do not invent impression counts.

**Agent 4 — Draft writer.** Write three posts for the named audience. Tag the signal each one is aiming at. Default length: something a person would actually post.

**Agent 5 — Pack writer.** Signal list, scorecard, three drafts, do-not-do line, appendix.

**Human operator.** Delete any reach promise. Export Markdown. The model does not post to the buyer's account.

Stack to start: one LLM, a public GitHub read, a paste inbox, a Stripe Payment Link. No X write token in week one.

## Risks and mitigations

- Fake reach: if the public source does not name impressions, do not invent them. Write `not-in-record`.
- Stale algorithm: the public repo can lag the live ranker. Say the card scores the named commit, not today's private ranker.
- Overlap with ship-receipt distribution (2026-09-23): that pack is the launch-week floor for where a ship note goes. This pack is a score of ordinary posts against a ranking source.
- Overlap with wrong-room card (2026-10-08): that pack is a mis-sent message. This pack is a public post. Do not merge the files.
- Overlap with model-drop positioning (2026-09-29): that pack is a landing page after a model launch. This pack is the feed.
- Account safety: do not take the buyer's X password or post on their behalf in week one.
- ToS: read public posts and a public repo only.
